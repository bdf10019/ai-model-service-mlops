# 可視化維運與操作手冊｜0.3.0

## 建議日常旅程

登入→環境健康→選團隊→模型核對／按需啟動→正常推論→監控篩選／圖表鑽取→必要時有界負載→停止發送並等在途完成→停止模型→同步 MLflow→告警確認／恢復探索→安全備份。既有評測、獨立核准、發布與回滾沿用[走查](客製化與發布走查.md)。

一般使用者只看自己的請求，不能啟動負載、改告警、備份還原；複核者可看安裝的授權工作、確認告警與同步 MLflow；管理者另有負載／政策／備份／引擎控制。Profile 不代表租戶隔離；全機資源樣本是共同主機，不包含其他程序名稱或私人內容。

## 監控數據定義

監控查詢固定 1／5／60 分鐘，以任務建立時間選取，最多 3000 筆。模型、設定版本與狀態篩選只影響其授權工作。預設看 Q8，Fixture 需明確選擇；圖表每 5 秒刷新，時段 12 格、任務 ID 可鑽取 Trace／版本。選完整生成或排隊 P95 圖時，無有效時間樣本顯示「無樣本」。

| 名稱 | 定義／分母 |
|---|---|
| 請求量 | 時窗內推論任務數，包含尚未終態；不混入評測批次 |
| 成功率 | completed 或 needs_review 數／所有終態數；複核需求不是品質通過 |
| 錯誤率 | failed／所有終態；cancelled留在分母，但不列failed |
| HTTP 接受時間 | POST /api/inferences 返回接受或拒絕所需時間；不是非同步生成完成時間 |
| 排隊時間 | 任務建立至取得引擎槽 |
| 完整生成時間 | 引擎完整回應，非串流；不含排隊 |
| 任務總時間 | 任務建立至完成；含排隊與驗證，不等於單純相加後的 HTTP 周轉 |
| 客戶端周轉 | 負載客戶端提交到觀測終態，含網路／輪詢開銷 |
| P50/P95 | 對實際可取得數值做線性樣本百分位，各自帶分母；無值null |
| TTFT | 未實作逐Token串流，null，完整生成不得代替 |
| 主機CPU/RAM/GPU/VRAM | 真實定期採樣，非單任務資源歸因；缺GPU或採樣錯誤顯示原因 |

無法歸屬任務的 HTTP 拒絕只在未篩選的管理／複核安裝摘要顯示；operator 不會因此取得別人的 Trace。監控中的「檢視指標輸出」是受登入角色保護的固定 1 小時安裝總量，含 Fixture，與目前圖表篩選無關；只提供 Prometheus 指標格式，没有常駐 Prometheus／Grafana。

## 有界負載

管理者到「負載與實驗追蹤」，選已保存設定、Q8或明示Fixture，以及固定 `synthetic-smoke-v1` 合成資料。預熱最多2筆且不納入測量；請求數1–20、併發1–3、逾時2–60秒、發送預算5–120秒。建議單併發、6筆＋1預熱，確認會影響本機服務後才啟動。

負載目標由服務實際監聽埠固定為 loopback，不接受任意 URL／外部代理／重導。真實 HTTP 經原登入／CSRF、有限佇列及引擎，設定啟動即固定，與正式 active 路由分開標示為沙盒負載。最多一個負載工作；其執行期間拒絕啟停引擎、評測、發布、回滾與恢復，避免兩批之間發生設定切換；普通推論仍走原有限佇列。

開始可用 RAM 至少768MiB，批次及採樣低於512MiB或VRAM不足時停止發送；3筆後錯誤超過50%亦停止。停止按鈕取消本工作尚未開始的請求，已取得引擎槽的工作等待安全完成，不殺其他程序。發送預算不是全程硬截止：既有生成最多60秒及有界排空可能延後收尾；請求觀測期限到達也不冒充引擎已取消。

以真正完成筆數顯示進度。逐筆延遲图與表格可以鑽取；成功率不等於任務品質。比較僅在模型／資料／程式與固定控制一致時給公平delta；不同併發可並列但標示不相容。匯出為去識別投影，`source_sha256` 是封存來源参照，不是投影 JSON 自身雜湊；不要當作原 sealed report。

## 客製化本機告警

在設定中心選團隊、編輯門檻／觀測窗／樣本／持續與恢復，先驗證、看 Fixture 情境及差異，再保存版本並確認套用。選原預設或舊版本重新套用就是政策還原；不会刪除歷史。

延遲／錯誤率／排隊需要至少3個終態Q8樣本，不因1筆波動告警；模型不可用與主機RAM為健康條件，不以請求樣本遮蔽。預設超標持續10秒進入firing；恢復條件持續10秒進resolved。延遲／錯誤／排隊須低至門檻×0.8；RAM需高於門檻÷0.8。沒有足夠樣本不能把空窗誤當正常。告警列顯示原因值、觀测n、門檻、政策hash、任務及事件時間軸。

維修2000ms／20%／排隊2000ms／RAM768MiB；設備1500ms／10%／1000ms／1024MiB。同3筆1800ms，設備觸發而維修保持正常；0.9GiB资源預覽亦如此。預覽明示Fixture，不持久化，不提供注入任意監控指標API。模型按需停止後仍会产生「模型不可用」告警，確認只記錄ack，不能偽裝恢復。無郵件／外部通知／自動回滾。

## MLflow 按需同步

已提供作品內 `.venv-mlflow` 鎖版環境；重建選用功能時執行 `scripts/bootstrap-tracking.ps1`，它只建立作品內環境及必要依賴，不安裝系统工具。一般控制台與模型不依賴MLflow啟動。

先停止模型再同步，降低RAM壓力。在評測／負載頁選完成的真實報告，按「同步／安全重試 MLflow」。本機 SQLite＋artifact references 使用 [MLflow 本機資料庫方式](https://www.mlflow.org/docs/latest/ml/tracking/tutorials/local-database/)，沒有外部帳號、server或tracking URL。控制台顯示sync狀態、原因、Run／experiment ID、實際參數／指標及產物参照；不傳入私人原文。

原封存SHA驗證後才同步；以來源SHA tag查找既有Run，重試不建立第二份，完整同步後重按直接回同ID。失敗原報告照常保留，補依賴／資源後重試。worker啟動RAM至少512MiB、RSS上限512MiB、主機硬底線256MiB、60秒期限，只中止自己worker。資料庫在state內，不對外公開；worker數據可於控制台探索，不需另啟MLflow UI。

新真實執行與歷史匯入用途分開標示，保留集重跑保留已觀測用途。參數與實驗不等於訓練證據。[MlflowClient](https://www.mlflow.org/docs/latest/api_reference/python_api/mlflow.client.html)及[Run查找](https://www.mlflow.org/docs/latest/ml/search/search-runs/)核對來源tag去重。發布／核准／active只由控制台資料庫作權威，MLflow無active/released狀態或Registry。程序中斷在完整標記前可重試同Run；部分metric寫入可能有重复歷史點，不宣稱跨程序事务exactly-once。

備份操作與資料排除見[備份契約](備份還原與交付契約.md)。本機版本仍無SSO／多租戶／公網TLS，不適合直接對外開放。
