# 備份還原與交付契約｜0.3.0

本輪交付**安全業務備份→全新隔離測試安裝還原**。不是現有安裝覆寫、完整災難復原或發布狀態搬遷；管理者權限由後端驗證，使用既有CSRF及32KiB單次請求限制。

## 包含與排除

| 類型 | 包含 | 排除／用途 |
|---|---|---|
| 設定 | 完整受驗證Profile、原SHA、selected标記、不可變版本 | 沒有Secret欄位；不得SQL／URL／命令注入 |
| 告警政策 | 受限policy、原SHA、所選版本 | 不搬當前告警／確認者／通知憑證 |
| 評測／負載 | 固定欄位歷史摘要、指標、config/model/dataset/report SHA参照 | 不含逐筆原文／結果、完整sealed原報告，不能直接通過發布 |
| 發布 | 歷史metadata、model/config/report/bundle参照 | 不重建active／previous、批准權威或使用者身份 |
| 模型 | 固定產物SHA及manifestSHA、取得契約参照 | 不包权重／DLL；還原不讀權重驗證檔案 |
| 認證／私人資料 | 無 | Session、cookie、CSRF、帳號、密碼雜湊、密鑰、未授權原文、私人Trace／引擎log、MLflowDB及產物cache均排除 |

業務摘要的 `record_use=historical_import_only_no_release_authority` 明示匯入用途。完整原始報告仍保留於來源安裝與私有reports，沒有打包成公開成果。模型重新取得依[來源與產物契約](模型來源與產物契約.md)、`schemas/model-import.json`；現有來源採只讀匯入，核對授權／版本／SHA，不自動下載大型權重。隔離收據 `model_reference_verified=true`，`model_file_verified=false`，兩者不能混稱。

## 格式、完整性與限制

固定 `console-business-backup-v1`、產品 `0.3.0`；每record namespace/id/data/SHA，外層bundleSHA。固定五個namespace，最多各64筆、合計256筆、512KiB；目前是有界最近業務紀錄，不承諾任意大型歷史全備份。超过界限明確拒絕，不靜默壓縮或省略聲稱完整。

下載由後端產生canonical UTF-8原始bytes並base64封裝，前端直接還原bytes下載，不將JSON parse後重序列化，避免`0.0`變`0`造成SHA不一致。檔案bytesSHA、bundleSHA、每recordSHA及原config／policySHA分層核對；數值有限且未知欄位／重複ID／Secret／錯模型參照／無設定参照拒絕。SHA是完整性索引，不是來源數位簽章；本機能修改原檔的人仍可能重算全部SHA，不宣稱防惡意管理員篡改。

上傳最多2個記憶體slot、120秒；每段原始≤12000bytes／base64≤16000chars、最多44段，單次依然≤32KiB。先宣告bytecount/SHA，逐段上傳、完成時核對總數／雜湊／格式版本／相容性。未完成、過期或不足數量不能還原。

## 介面流程與隔離驗證

備份頁→匯出→保存下載→選檔→字節進度→完整性與相容性預覽（種類／筆數／模型參照／排除）→勾選隔離影響→確認。後端再驗bundleSHA及typed confirmation，產生 `state/restores/<新UUID>`，檢查解析路徑在作品state內、建立全新Store，事務保存，不接受使用者輸入覆寫目標。

configs／alert_policies保留immutable版本並恢復selected設定；其他放 `imported_evaluations/loads/releases`，不冒充新執行／原正式發布。收據確認筆數、所選版本、模型参照、users=0、沒有active，以及相對安裝路徑；錯誤不顯示成功。

自動整合測試真正以新隔離DB建立產品app，讀取恢復的選定品牌、設定版本、政策與必要業務紀錄；目前安裝帳號／記錄／active沒有改動。E2E另從真正介面下載原bytes、上傳驗證及還原，手機390px／鍵盤可用。沒有為測試覆寫使用者DB，也沒有把E2E帳號複製進正式安裝。

要轉成可使用的新安裝仍須自行一次性引導新管理者、從既有可信模型來源取得產物並完整hash驗證，重新評測／核准／發布；本輪不自動搬憑證／權威狀態。完整稽核歷史、密鑰重建、分卷、大規模一致性與真實災難復原走查屬後續必要缺口。
