# 複核資料生命週期與備份契約｜0.4.1

本契約適用於本機單安裝，不代表多租戶、完整災難復原或永久證據庫。來源保存同意與人工業務內容的備份確認是兩個不同的操作。

| 資料 | 保存方式與期限 | 到期／重啟後 | 備份 |
|---|---|---|---|
| 一般 input/raw/post/context | 預設記憶體15分鐘；重啟可能提前不可取得 | 清理來源；不能接受、修正或繼續批准該複核 | 不納入 |
| 明確同意的待複核來源 | 本機 `review_evidence` 保存7日；最多100筆，包含在途同意任務 | 啟動、存取／收件匣及每30秒檢查；刪除到期資料列與記憶體來源 | 不納入；不因備份延長7日 |
| 原創合成示例 | 公開授權、標示 synthetic_sample，無私人證據自動期限 | 仍可探索，不能冒充使用者來源 | 複核業務備份仍排除來源／證據span |
| 人工摘要、理由、修正及歷史 | 本機 `reviews`，沒有自動到期，直到授權退役／移除安裝 | 來源到期後仍保留業務歷史；已完成的最終人工結果可匯出 | 管理者預覽並明確確認後，才納入專用業務備份 |
| 業務複核政策及設定 | 不可變版本、SHA與任務固定快照；沒有自動到期 | 舊任務仍引用原版本 | 專用備份保存必要歷史參照 |

**保存期間不可覆寫，不代表永久保存。** 模型原始、政策後與人工結果分開；人工處理不修改模型分數，也不核准模型發布。七日清理使用SQLite資料列刪除及 `secure_delete`，不承諾作業系統快取、磁碟、舊複本或外部備份安全抹除。摘要與理由仍可能含私人資料或使用者抄入的事實；排除原始欄位不代表人工內容已匿名。

本輪不增加任意保存期限、批次刪除管理或外部通知。需改業務內容保留期或集中退役流程，另行制定授權規則。

## 兩個備份契約

原 `console-business-backup-v1` 維持原業務範圍，仍不含 reviews、review_policies、review_evidence。0.4.1修正其應用程式版本標記，接受0.3.0／0.4.0／0.4.1版本；補齊已存在holdout-v2的資料集參照相容性。它沒有被偷偷擴大成含私人複核內容的備份。

新增 **`console-review-business-backup-v1`**，Schema見 `schemas/review-business-backup-v1.json`；後端另執行投影欄位、歷史角色／理由、SHA、設定／業務政策參照驗證。它包含：

- 必要 configs／review_policies 版本、SHA、選用參照。
- 複核任務／Trace／模型／設定／業務政策參照、状态、保存方式及期限。
- 人工結果、理由、修正、操作者／時間／歷史；evidence_spans一律清空。
- 既有模型與manifest SHA參照，不含權重。

一律排除原始輸入、raw、政策後原始結果、context、原文證據span、review_evidence、登入Session、密碼雜湊、帳號資料、秘密值、模型權重及 active／released 權威。業務操作者的參照標識仍會出現在歷史，不等於備份帳号與憑證。

每個namespace最多64筆、合計192筆、512KiB。超過上限拒絕整包，不截斷歷史參照。SHA為本機完整性校驗，並非簽章、獨立來源認證或對本機管理者的防篡改保證。

## 介面匯出

1. admin 開啟「備份與隔離還原」→「預覽複核備份範圍」。查看包含／排除、筆數及實際人工內容。
2. 確認人工内容有權在授權本機範圍備份，勾選「確認人工私人內容備份」。不是允許原始證據匯出。
3. 按「確認匯出複核業務備份」。後端要求admin、同一操作者的預覽票、固定bundle SHA及明確確認；票有效120秒。過期需重新預覽，不能直接匯出最新變動而沿用舊確認。
4. 下載檔案自行放在授權範圍，不提交Git、不傳外部模型服務。

## 隔離還原

1. 選檔→分塊上傳→格式／版本／SHA／相容性／所有歷史參照驗證。無效檔顯示失敗，無確認還原入口。
2. 預覽影響，確認只建立**新的** `state/review-restores/<UUID>`（測試安裝則在自身tmp下）。不覆寫目前資料庫。
3. 後端寫入新的Store，核對每筆存在、帳號0、來源證據0；保存實際收據。
4. 按「探索還原複核歷史」。可看設定、人工結果及歷史，input/raw/post顯示缺少。

還原複核全部標記 `imported_from_backup`／唯讀。即使狀態是accepted，也只是歷史業務狀態；缺少來源不能重新接受、修正、補第二人批准或成為模型發布證據，後端409拒絕。沒有恢復登入、任務、評測、active發布或引擎。已完成的歷史最終人工結果可以匯出，不改模型指標。

模型參照匹配不等於重新驗證權重檔：收據分開 `model_reference_verified=true` 與 `model_file_verified=false`。真正使用模型時，依 `模型來源與產物契約.md` 重新取得允許授權產物，核對SHA及manifest，再於模型頁驗證；備份本身不啟動引擎。

自動驗證使用全新隔離安裝與受控時鐘，不覆寫使用者資料，不等待七日。參照 `tests/test_review_closure.py` 和 `frontend/e2e/closure.spec.ts`。
