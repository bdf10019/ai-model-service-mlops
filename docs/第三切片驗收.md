# 第三切片驗收｜0.3.0 可視化維運、客製化監控與交付驗證

日期：2026-09-14。沿用 0.2.0，同一程式、既有登入與版本治理；只在第一個作品新增。第二切片驗收及原 24 筆回歸資料保留，歷史報告按原 bytes 歸檔，沒有修改舊成績或重新簽署。

## 1. 使用者新增可操作的功能

- **監控與本機告警**：模型、設定版本、時間窗及任務狀態篩選；請求量、成功／錯誤率、HTTP 接受時間、排隊／完整生成／任務總時間 P50/P95。時段及延遲圖可鑽取任務、Trace 與版本；CPU、RAM、程序 RSS、GPU/VRAM 取真實主機樣本，缺值顯示原因。可從介面查看受權限保護的 Prometheus 格式指標，尚無 Prometheus 伺服器。
- **負載與實驗追蹤**：選固定模型／設定、併發、請求數、預熱、逾時及發送預算，確認本機影響後啟動；實際筆數進度、安全停止、逐筆延遲圖／Trace、比較、環境與原始數據報告匯出。併發等控制不同時，明示不能做公平增減比較。
- **設定中心監控政策**：表單驗證、明示 Fixture 情境預覽、差異、保存版本、明確套用及還原既有政策；告警原因、確認、持續／恢復事件可探索。確認不等於恢復，沒有外部通知。
- **評測頁**：保留原 24 筆回歸集，加入固定 16 筆保留集與候選凍結檢查；揭露原始／政策後結果、分母、失敗案例及首次／已觀測用途。
- **備份與隔離還原**：管理者匯出安全業務備份、選檔分段驗證、預覽、影響確認、還原到作品內全新隔離安裝及查看驗證收據。不覆寫現有安裝。

各新增頁面有載入、空狀態、驗證／服務錯誤、無權限及恢復提示，後端授權與介面同步。[互動矩陣](第三切片功能覆蓋矩陣.md)界定本輪入口；整份計畫仍有必要缺口。

## 2. 客製化造成的實際差異

沿用品牌、生成參數、必填欄位、品質门檻、一／雙獨立複核與維護發布政策；本輪新增版本化告警政策：

| 預設政策 | 維修服務 | 設備管理 |
|---|---:|---:|
| 完整生成 P95 | 2000 ms | 1500 ms |
| 任務錯誤率 | 20% | 10% |
| 排隊 P95 | 2000 ms | 1000 ms |
| 可用主機 RAM | 768 MiB | 1024 MiB |
| 觀測窗／最低終態樣本 | 60 秒／3 | 60 秒／3 |
| 持續／恢復時間 | 10／10 秒 | 10／10 秒 |
| 恢復比例 | 0.8 | 0.8 |

受控測試把 3 筆 Q8 任務完整生成設為 1800 ms，持續 11 秒：維修政策保持正常、設備政策觸發。較低觀測持續恢復時間後，設備告警實際進入 resolved；確認操作保留 firing。0.9 GiB 可用 RAM 的 Fixture 預覽同樣讓設備觸發而維修不觸發。這些是**受控邏輯測試／Fixture 預覽**，沒有冒充 GPU 故障實測。沒有足夠新樣本不能自動解除仍在觸發的延遲告警。

政策更新不改舊告警版本，不影響啟動時固定的推論／負載設定，也不能降低發布安全底線。詳細操作見[維運手冊](可視化維運與操作手冊.md)。

## 3. 真實負載及資源預算

Windows 11 Home 26200、RAM 15.61 GiB、RTX 5060 Laptop 8151 MiB。開始盤點可用 RAM 2.42 GiB、VRAM 使用 527 MiB；沒有停止其他應用。下表是真實自迴路 HTTP → 現有佇列 → 作品 Q8 引擎，非 Fixture。兩次各 6 筆測量、另外 1 筆預熱；相同 service 設定、320 tokens、seed 42、temperature 0、固定合成資料。發送預算 60 秒、請求觀測逾時 20 秒。

|---|---:|---:|

TTFT 未提供。只有 6 筆／組，這是有界基準，不能建立通用 SLO；併發不同的兩组並列，不宣稱公平版本回歸。主機採樣觀察到 Q8 使用期間可用 RAM 最低約 1.77 GiB、VRAM 使用最高約 2872 MiB；負載 B 開始瞬間 RAM 為 1.76 GiB。這些是時間點主機數據，不是單請求耗用，也不是系統資源預留。

建議控制台＋單 Q8、單併發；測量最多 6 筆＋1 預熱。允許的硬界限為併發 1–3、測量 1–20、預熱 0–2、發送 5–120 秒，只有一個負載工作；RAM 開始至少 768 MiB，低於 512 MiB 停止發送，VRAM 餘裕不足亦停止。普通請求沿用有限佇列，負載逐小批讓出發送機會。不能保證普通請求完全沒有延遲影響；安全停止等待已開始的引擎工作，發送預算不是全程硬截止。

## 5. MLflow、備份還原與容器實際狀態

**MLflow 已實跑**：作品內可選独立環境 `mlflow-skinny 3.16.0`，本機 SQLite 及產物參照，按需 worker，沒有常駐伺服器。真實評測／負載各同步一個 Run：`8015f022955946f081fdfd4190e95db3`／`3ceae0a0709d40998a5add4f933408d0`，均有參數、指標、來源 SHA 與產物參照；重按同步 Run ID 相同、attempts 仍 1。worker 實測峰值 RSS 141.02／134.58 MiB，設定上限 512 MiB，主機低於 256 MiB 中止自己 worker。模型先停止再同步。缺依賴／失敗／安全重試以控制測試驗證；原報告保留。MLflow 無發布權威、沒有 Model Registry；評測重跑的已觀測用途保留在 tag。

**備份還原已實跑**：真正介面下載原始 canonical bytes → 分段上傳與完整性／相容驗證 → 確認 → 新隔離 SQLite 安裝。單元整合測試另啟動還原安裝的產品服務，核對所選設定、政策、業務紀錄及模型参照；users=0、active release 未設定、目前安裝不變。權重不打包，僅驗證來源参照相符，不宣稱還原時核對權重檔案；須後續從模型頁做完整檔案驗證。業務歷史摘要不等於完整原評測／稽核備份，不能用匯入摘要直接發布。[備份契約](備份還原與交付契約.md)。

**容器未實跑**：最新工具盤點仍沒有可用 Docker／Compose，WSL 尚未可用；沒有安裝／系統變更／拉映像／建置／容器請求。0.3.0 Fixture 容器設定、健康檢查、持久化與重啟驗證腳本已有，Linux GPU adapter 及完整監控 Compose 尚缺。需要另行同意的確切環境動作見[容器設定](容器部署設定.md)。不把檔案存在當部署完成。

## 測試證據與既有流程回歸

後端 **45 通過**；前端 **11 通過**；端到端 **13 種案例最終均有通過證據，採分批修正重驗**。最初完整 13 案例批次為 11 通過／2 失敗；修正備份 JSON 跨語言 `0.0` 重序列化雜湊差異，以及測試停止狀態選擇器後，新增維運 3 案例全部通過，再以 Fixture 專項重驗新增圖表及指標出口。不是同一批 13/13 報告，也沒有改寫失敗批次。

## 6. 距離整體計畫的必要缺口

1. **品質優先**：本保留集已觀測，修正否定／已恢復／混合事件與拒答後把它列入開發／回歸；另建立新、獨立複核的凍結保留集。不能重用本集作未見認證。
2. Docker／Compose 真實安裝驗證、持久化／重啟／故障恢復，及 Linux 真實 GPU 引擎 adapter；需要系統與大型下載同意。
3. MLflow Model Registry 的產物登記與唯讀參照，維持控制台唯一發布權威；真實 Prometheus 收集器／監控服務尚未執行。
4. 真正 Token 串流、Token-level TTFT、必要 OpenAI-compatible endpoint；多權重版本切換尚未驗證。
5. 人工推論結果批准／退回、帳號停用／密碼恢復、一鍵安全重播、全量證據匯出與完整供應鏈／授權稽核。
6. 業務備份是新隔離安裝恢復；完整災難復原、憑證重建走查、完整稽核與大型歷史資料分卷仍缺。Profile 不是多租戶隔離。

下一最小交付建議先做品質修正＋全新保留集＋必要相容端點的完整介面／後端／測試切片；容器環境另獨立處理。[全計畫實作追蹤](實作覆蓋追蹤.md)不把複合功能部分完成算作全作品 100%。
