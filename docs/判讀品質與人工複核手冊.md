# 判讀品質與人工複核手冊｜0.4.1

1. 一般使用者登入，Playground 選模型與實際設定版本。預設原文與輸出只留記憶體15分鐘；可明確勾選「本機複核證據保存同意」，僅需複核結果的來源於本機保存7日，跨重啟可處理。最多100筆包含在途同意任務；滿額503，不偷偷改保留方式。到期清理不承諾磁碟安全抹除。
2. 「判讀錯誤與證據」可選否定、歷史、恢復、多事件、惡意、政策誤升級、評分歧義等類型，逐筆看首次16筆的原文、固定標註、原始／政策後差異與來源SHA。分析由AI完成，没有獨立人員複核。
3. 「評測與版本比較」選固定資料版本，鑽取各指標定義、分子／分母及案例。新v2指標將事件／程度、應複核召回、不必要介入、自動比例與自動案例品質分開；人工作業不加入模型分數。
4. 「人工複核收件匣」依狀態、原因、Provider、設定版本篩選；點任務看輸入、模型原始、政策後、Trace與固定業務政策。一般使用者只看自己的結果，不能提交複核。
5. 符合固定角色的人可接受、修正允許欄位、退回、標記資訊不足。修正必填理由，設備版另選逐字證據參照；退回／資訊不足不要求不存在的證據。原始／政策後結果在保存期間不可覆寫，不代表永久保存；人工結果另外保存，不把人工作業改成模型正確。
6. 維修預設允許reviewer/admin，理由8字，事件／程度／摘要可修正，高風險一人。設備允許reviewer，理由16字，加缺失資訊，高風險兩名不同reviewer；第一人只是提案，第二人獨立確認後才有最終結果。admin不能代替設備reviewer。
7. 版本衝突保留未套用草稿提示，按「重新載入最新複核紀錄」清除草稿，再次確認最新狀態。相同Idempotency-Key與相同提交只形成一次歷史；同鍵不同內容或完成後重交拒絕。
8. 最終結果可匯出JSON，綁定操作者／時間／任務／模型／設定／政策／處理歷史及投影SHA；非合成原文與原始證據不包含在人工結果匯出。使用者自填摘要及理由可能有私人內容，匯出應留在授權本機範圍。
9. 設定中心的「版本化業務複核政策」可表單驗證、Fixture預覽、差異、保存、套用及選回預設／舊版。此政策是獨立不可變設定紀錄，於任務提交固定；切換Profile不提升登入角色，不改已啟動任務。

人工複核是業務分流處理。所有safe_actions只是受限建議代碼，没有設備命令接口；高危害不可降到安全底線以下。人工接受不核准模型發布，發布仍由既有獨立核准流程管理。

來源到期／重啟而未同意保存時，介面明示不可取得並阻擋處理，需重新推論補證據；已保存業務歷史仍可探索。來源保存與人工作業紀錄位於Git忽略的state或隔離測試tmp，沒有送外部模型。

每筆詳細資料有「複核證據保存與到期」，顯示記憶體15分鐘、本機7日或合成案例，以及實際到期時間與可操作原因。七日來源在啟動、存取及每30秒清理；到期後接受／修正由後端410阻擋，不能靠Profile或重複提交繞過。可看已存業務歷史、匯出已有最終人工結果，或重新推論建立有來源的新任務。

人工摘要、理由、修正、處理歷史和版本化業務政策沒有自動到期，保留在授權本機安裝直到授權退役／移除；其中仍可能有私人資料。來源期限與業務紀錄期限分開，不因原文到期推定人工內容已清除。

原業務備份v1仍排除review_evidence、reviews、review_policies、Session、帳密。管理者另於「備份與隔離還原」預覽專用 `console-review-business-backup-v1`，檢查人工內容、明確確認後才可下載；原始輸入、raw、政策後原始結果及證據span仍不納入。上傳可驗證及预覽，只新建隔離安裝；按「探索還原複核歷史」查看實際結果。還原資料沒有原始證據、全部唯讀，不能重新批准或作發布證據。詳見[生命週期與備份契約](複核資料生命週期與備份契約.md)。

「判讀錯誤與證據」新增應用程式／權重／提示政策／服務發布狀態、已知修正案例及三組已觀測報告鑽取。0.4.1不等於模型發布；triage-v4只是既有回歸基線，triage-v5及修補候選triage-v5.1均未發布。原v5使用原safety-v3，新候選使用safety-v3.1，舊報告不自動重新套用政策；同Q8回滾始終是服務設定回滾。首版是單安裝角色授權，並非多租戶隔離。
