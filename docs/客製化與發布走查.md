# 客製化與發布走查

日期：2026-09-14；同一套核心程式，不複製客戶專案。設定與版本入口在產品頁內，安裝腳本不替代日常操作。

## 兩組原創設定

| 行為 | 維修服務 | 設備管理 |
|---|---|---|
| 品牌／術語 | 維修分流台、案件 | 設備守望台、設備事件 |
| 建議提示／生成 | triage-v4，320 tokens、seed 42、temperature 0 | triage-v4，384 tokens、seed 84、temperature 0 |
| 輸入欄位 | 事件、設備編號 | 再加 asset_criticality、maintenance_window 必填欄位 |
| 原始任務品質門檻 | 80% | 85% |
| 複核 | high、critical、unknown 與共同安全底線 | 另加 medium、所有關鍵設備 |
| 核准／發布 | 一名非提案者 reviewer；admin 套用 | 兩名不同非提案者 reviewer；admin 維護確認後套用 |
| 排隊 | 4 筆、10 秒 | 2 筆、5 秒 |

產物固定同一已驗證 Q8；不同生成參數確實送到引擎。設備版改必填輸入／複核政策，不宣稱輸出 Schema 改成另一任務。此次真實評測後 review_rate 維修 50%、設備 80%，不能以配色替代這些行為差異。

表單支援品牌／術語、受限提示版本、Token／seed／temperature、必要欄位、品質門檻、佇列／逾時及發布政策。Schema／範圍驗證由後端執行；設備最低雙核准及維護政策不可降低。Logo／自由儀表板布局尚未交付，不用未啟用設定宣稱客製成功。

## 完整 Demo

1. 用自己的 admin 登入，健康頁確認資源，模型頁核對／啟動 Q8。到帳號頁建立 reviewer；設備需要第二名。
2. 設定頁選維修，預覽初始 v1。評測頁選 Q8、service-v1、equipment-triage-v1；執行 24 筆。查看原始／政策後數據與失敗案例，v1 無門檻不能發布。
3. 設定頁載入建議、調整受限欄位、驗證／範例預覽、看差異、保存 A；admin 套用為沙盒候選。發布要求不是在舊報告上改一個數字。
4. 以 A 重新評測，比較 v1／A，鑽取 raw 失敗與安全層修正。發布頁檢查 gate、建立固定 bundle 提案。
5. 登出並用獨立 reviewer 登入，核對版本／報告後核准。admin 再登入，確認影響及維護條件後發布；等待兩筆真實探針及任務結果。202 與載入狀態不是成功。
6. Playground 自動模式執行合成真實推論，詳情確認 A 的 release_id、設定 hash、320 tokens／seed 42。不要選 Fixture 驗證正式發布。
7. 新存 B：384 tokens／seed 84；套用沙盒、重評、比較、獨立核准、admin 發布。新真實推論應使用 B。
8. 發布頁檢視 previous A，確認回滾影響後回滾；查看真實探針成功，再從 Playground 自動模式實際推論。設定／引擎參數應回到 A，沙盒候選 B 保留。
9. 設備流程載入其建議、保存／重評／提案；第一位 reviewer 核准仍為 1/2，第二名核准才合格。沒有維護確認不能套用；發布後真實參數 384／84，設備重要性與維護欄位、複核政策生效。

## 設定往返與恢復

JSON 匯入最多 32 KiB，先進表單草稿並經後端預覽驗證；未知／秘密值／任意程式／非法 URL、SQL、命令與超範圍參數拒絕，不回顯秘密。匯出只含受限設定，不包含 session 或 token。還原預設／上一版需確認，建立新不可變版本，之後仍需明確選候選、重評與發布。

失敗時依明確原因修復：過期→重評；候選改變→選正確版本並重評；品質不足→改善提示／模型而非隱藏失敗；模型不可用→模型頁核對／啟動；工作繁忙→等待佇列排空；發布／回滾失敗→看任務／Trace，確認舊版是否恢復或 ready=false，再用發布頁恢復現有 active。

評測圖表、逐筆 raw／post、設定差異、發布拓樸、核准／操作時間軸均連回實際資料。匯出為去識別合成投影，來源 hash 可追查，不是重新簽署過的原始報告。
