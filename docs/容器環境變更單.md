# 下一階段容器環境變更單｜待使用者同意

日期：2026-09-14。狀態：只完成影響分析，未下載安裝程式、安裝、啟用功能、重開機或拉取容器映像。方向確認與開始產品實作不代表系統變更授權。

## 建議方案

安裝／啟用現代 WSL 2 與 Docker Desktop 的 Linux container backend。先不額外安裝 Ubuntu 或啟用 Kubernetes，不調整 NVIDIA 驅動，不登入 Docker Hub，不建立雲端資源。Docker 官方說明不要求另外安裝特定 Linux 發行版：[WSL backend 文件](https://docs.docker.com/desktop/features/wsl/)。

系統安裝程式、Windows 功能、必要 runtime 及 Docker 自身設定屬系統變更，會有作品目錄外的必要檔案；需明確同意此例外。產品原始碼、模型、狀態、測試與報告仍集中在作品內。

Docker 的持久虛擬磁碟優先指定本作品 `state/container-runtime/`；官方提供 WSL data-root 安裝選項或設定頁調整磁碟位置。先核對選定安裝模式是否接受該選項，若不支援或需要其他位置，回報後才決定，不靜默採外部資料位置：[Windows 安裝文件](https://docs.docker.com/desktop/setup/install/windows-install/)。

## 影響與資源

- 首次啟用 WSL／虛擬平台可能要求管理者權限及重新開機，需保存其他應用程式工作；不自行強制重開。
- 會增加系統 runtime、VM 磁碟與背景資源占用。估計需要數 GB 起的磁碟；完整 GPU／MLflow 映像可能進一步增加。這是容量估算，不是已下載大小。
- 本機只有約 16 GB RAM。六筆真實 Q8 冒煙時，可用 RAM 約 0.96–1.06 GiB、VRAM 2767–2770 MiB。下一步先停止模型並重新查資源，再討論容器試跑；不自行關閉其他程式。
- 如採 WSL 記憶體／回收限制，可能需更新系統级 WSL 設定。必須先備份原設定、展示差異與影響，並限制只改本方案需要的內容。尚未承諾固定 RAM 額度。
- Windows Home 使用 Linux containers；不啟用 Windows containers、企業登入或 Docker socket 公開服務。

## 安裝與下載的控制

取得同意後，先選定官方安裝版本、核對系統需求與安裝大小，再實際下載安裝。大型容器映像的來源、固定版本／digest、容量與用途另列清單；沒有同意不得直接拉取大型 GPU 映像。

個人開發方案不需付費模型 API；不自行接受需要付費的方案或建立帳號。授權適用條件依官方安裝文件確認，若用途或條件不符則停止並回報。

## 驗證與恢復

1. 確認 WSL version、Docker／Compose 命令可用及 data-root 實際位置。
2. 以固定小型本機測試容器驗證服務可啟動，端口僅綁 loopback。
3. 再將已完成切片放進容器，跑真實健康／請求與前端旅程；GPU、模型容器與完整 Compose 另記結果，不能把 API 容器成功當成整組部署成功。
4. 測資源及停止／重啟，保留前後設定與證據。

不成功時停止本作品容器，保留日誌與資料；不執行全域 prune、不清除其他映像／volume，不任意 unregister WSL 發行版。系統 runtime 的移除或 Windows 功能還原先說明影響並另行確認。VM 資料不刪除，除非使用者明確要求且驗證目標範圍。
