# 本機產品收尾驗收｜0.4.1

日期：2026-09-15。本輪只修補既有缺陷、複核來源生命週期與最小業務備份，不新增權重、訓練、保留集、帳號管理、Registry、串流、容器或外部服務。上層計畫書及八月作品不修改，歷史資料、首次報告與驗收數字保留。

## 1. 已知政策缺陷及證據

兩項原strict xfail已移除預期失敗裝飾，原輸入及斷言不变，轉為一般通過測試。另有23個通用語句／安全反例：未發生、尚未發生、已發生、否定後肯定／轉折；不存在與無法排除／尚未確認／雙重否定；重大歷史事故暫復及完整恢復；手冊／假設／反事實與現場真實回報；同句假設後的真實危害。沒有案例ID查表或僅匹配測試句子的規則。

新 `triage-v5.1` 提示與 `safety-floor-v3.1`／`clause-evidence-v1.1` 分析子句否定範圍，將不確定性與不存在分開；有非事實語境的引用不設危害底線，現場回報、实际重大歷史事故與後續新的肯定危害仍設底線。判斷保留逐字offset及理由，圖表案例能展開原始／政策後/context來源。

原v5與safety-v3完整另存 `context_quality_v3.py`；原v4由未修改的 `legacy_domain.py` 執行。舊報告不自動套新政策。新版不關閉危害保護、不降低發布門檻；人工修改也執行新安全底線，但不覆寫原始結果或模型分數。

新真實結果中h03／h08不再因「未／尚未超限」誤升high，h11不再把「不可把…當起火」當成critical，仍保留真實溫度超限的high。三筆由政策任務錯誤轉為正確。這證明已知缺陷修復，不代表所有中文語義已解決；分析仍是有界、可解釋的啟發式，沒有生產安全保證。

## 4. 複核保存、匯出與隔離還原

可在複核詳細頁查看原始／政策後／人工結果、保存方式、到期時間及不可操作原因。一般記憶體15分鐘；明確同意待複核來源本機7日；公開原創合成示例獨立標記。到期來源實際從review_evidence與記憶體刪除；接受／修正及後續批准由後端410阻擋。時間測試注入受控時鐘，不等待七日。

人工摘要、理由、修正、歷史與業務政策沒有自動到期，保留於授權本機安裝直到授權移除／退役；仍可能含私人內容。來源保存期間不可覆寫，不代表永久保存。維修8字理由／reviewer或admin／3欄位／一人，設備16字／reviewer／4欄位／證據參照／高風險不同兩人保持不變。Profile切換不提升登入角色或擴大來源同意。

專用業務備份版本 `console-review-business-backup-v1` 有管理者預覽、私人內容確認、固定SHA匯出；來源input/raw/post/context/evidence_spans與review_evidence全部排除。原general business-v1仍為另一契約，不含新複核紀錄。格式／版本／SHA／歷史參照／角色理由驗證後只新建隔離安裝；每筆實際核對，帳號0、來源0、無active發布。原安裝資料未覆寫。

還原保留設定／政策參照及人工歷史，原始缺少且全部唯讀；在新的create_app安裝中，後端409確實禁止再次批准／修正，人工結果不能作發布證據。可由介面探索實際還原歷史、匯出已有最終人工業務結果。收據只驗證模型參照，不宣稱權重檔已驗證。詳細规则、上限與步驟見[生命週期契約](複核資料生命週期與備份契約.md)、[操作手冊](判讀品質與人工複核手冊.md)、[本輪矩陣](本機產品收尾功能覆蓋矩陣.md)。
