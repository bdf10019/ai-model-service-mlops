## 2. 新可操作業務複核

新增「判讀錯誤與證據」及「人工複核收件匣」。可按類型探索來源、按狀態／原因／模型／設定篩選，接受、修正允許欄位、退回、資訊不足、第二人獨立確認、看歷史及匯出最終JSON。原始input/raw/post保持唯讀，人工結果另存任務／模型／設定／操作者／時間／版本；不改模型分數或發布狀態。

| 固定預設 | 維修 | 設備 |
|---|---|
| 品質候選參數 | triage-v5，320 tokens，seed42，temperature0 | triage-v5，384 tokens，seed84，temperature0 |
| 可改業務欄位 | event_type/severity/summary | 再加missing_information |
| 必要理由 | ≥8字 | ≥16字 |
| 可處理角色 | reviewer/admin | reviewer，admin不能代審 |
| 高風險 | 一人 | 兩名不同reviewer、逐字證據參照必填 |
| 中風險／關鍵設備 | 依原服務設定 | 中風險與關鍵設備需複核 |

差異来自版本化review_policies，任務提交固定整份政策與SHA；設定中心有表單、Schema、Fixture預覽、差異、新版本、套用、選回預設與旧版。Profile切換不加登入權限。SQLite交易驗revision，重複鍵相同payload不多寫歷史，不同payload拒絕；原始證據与模型／設定绑定改動拒絕。

一般原文預設15分鐘記憶體；明確勾選同意的待複核來源可本機保存7日、最多100筆含在途。未同意／到期來源不能接受或修正，明示需重推論；既有業務歷史可讀。人工自填摘要及理由會本機保存，原始證據不搬入最終匯出；所有新複核資料排除原備份v1。
