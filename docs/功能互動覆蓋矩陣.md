# 全功能互動覆蓋矩陣

日期：2026-09-14。狀態：全部為規劃，實作 0／34，驗收 0／34。規劃列覆蓋 34／34，不代表產品完成率；正式實作時依最終功能粒度擴充，不得把複合列當成只需一個測試。

角色 O=一般使用者、R=複核者、A=管理者。P01–P11 對應[頁面與流程](頁面與低擬真流程.md)。HTTP 契約為提議名称，尚未建立路由。所有 mutation 都執行後端 session／角色驗證，按需要驗證 idempotency key、If-Match 與 approval bundle hash。

## 共同契約

- 成功讀取回傳版本、來源時間與 evidence_kind；長任務提交回 202＋task_id，完成後由任務／事件查詢取得結果，202 不是工作成功。
- error 含 code、可安全顯示的 reason、request_id／trace_id、recoverable；不回顯 secrets 或私人路徑。
- 每個任務存 config_snapshot_hash、profile_version、model_digest、prompt/schema/policy_version、actor_id（匯出需去識別）、attempt、parent_task、時間與狀態。
- F01–F34 皆有 UI 入口。對應 V01–V34 為後續測試案例群名稱，尚未執行。

## 覆蓋率計算與範圍管理

「已驗收功能列／已承諾交付列」是功能覆蓋率；每列還須完成其適用的操作、讀取、錯誤、角色、狀態與證據子案例。範圍移除需記錄原因與使用者確認，不能為了湊 100% 隱藏缺口。

容器首次安裝／啟動、依賴設定、本機 Git 與 CI 是安裝維護工序，可有必要腳本；不把它們偽裝成日常產品功能。它們的部署結果與測試證據仍在 P01／P06／P11 可查。

進階候選不進首版已承諾分母：Kubernetes、多副本、共享狀態、全域流量限制、Shadow／Canary、自動回滾及故障注入工作台。確認進階範圍時，每項新增矩陣列與 UI＋後端＋測試，不能只有 infra 設定。
